# Research Project Brief

Write the shortest brief that conveys the scientific purpose, key targets and work required. Prefer omission over completeness when a detail does not help define the research.

Read [references/house-guide.md](references/house-guide.md) before drafting or revising. A supplied template, word limit or explicit user instruction takes precedence.

## Method

1. Identify the central technical problem and one governing aim.
2. Retain only facts, research questions, methods and outputs that define the work.
3. Group the work into a small number of distinct research strands.
4. State what must be done and what each strand is intended to establish.
5. Remove repeated context, administrative detail and speculative elaboration.
6. Write in direct British English and run the brevity check in the house guide.

## Default output

- Title
- Short project overview
- Aim
- Core research questions or targets
- Research strands, with concise work bullets
- Proposed experiments or modelling tasks, only where useful
- Expected outputs and starting resources, only if they add practical value

Do not add timelines, week-by-week plans, milestones, decision gates, tracking systems, reporting procedures, data-management sections, training inventories, risk registers, schedules or open-item appendices unless the user asks for them or they are essential to interpret the work.

## Constraints

- Do not invent evidence, collaborators, facilities, targets, programme requirements or references.
- Do not inflate brief notes into a comprehensive project plan.
- Do not repeat the same point in the overview, aim, questions, strands and outputs.
- Do not explain standard methods unless the explanation changes the scientific purpose.
- Keep conditional work visibly secondary in one short statement.
- If essential information is missing, use a minimal `[PLACEHOLDER]` or ask one focused question; do not create a long open-items list.
- For Word output, use the Documents skill and preserve any supplied template.
